# Project Importer PCF

A PCF control for model-driven applications that imports tasks into an active PSA project from a Microsoft Project `.mpp` file, an Excel `.xlsx` file, or another active PSA project. It can also browse and select projects from a Project Online PWA site.

The control also includes a **Test connection** action that calls the Azure diagnostic endpoint directly and displays the complete HTTP status and response body on screen. It does not require a project or file selection.

The control is multi-environment: every Azure Function request declares the Dataverse environment that hosts the control, so the same solution, Function URL and Function Key work in any environment. See [Multi-environment](#multi-environment).

The visual container uses a responsive fixed viewport of up to `760 × 680 px`, with an internal vertical scrollbar and a sticky header. The card is centered horizontally and vertically inside the available PCF area.

## Flow

1. The user selects **Import from .MPP file**, **Import from Excel**, **Import from Project**, or **Import from Project Online**.
2. The user searches for the destination `msdyn_project` record by `msdyn_subject`.
3. MPP mode uploads the selected file as `multipart/form-data`.
4. Excel mode uploads the selected `.xlsx` file as `multipart/form-data`.
5. Project mode searches for a different source project and posts both project GUIDs as JSON.
6. When an endpoint returns `202 Accepted` with a `statusUri`, the control polls it with the same Function Key until completion or failure. With an older Function that returns `statusQueryGetUri` instead, it polls that URL.
7. Project Online mode reads `mfd_posharepointurl` from the first active `mfd_pocopyprojectconfiguration` record. The user can edit and save the URL from the control.
8. **Connect to Project Online** opens the configured Custom Page as a centered dialog and passes the active configuration record through `entityName` and `recordId`.
9. Connection status changes to **Connected** only after the project-list request succeeds.
10. Project Online projects can be selected individually or through **Select all**. Expanding a project displays its tasks in a child grid.

Project Online mode does not start a migration. The migration action will be added through a separate Azure Function endpoint.

## Multi-environment

The control reads the address of the environment it runs in: `context.page.getClientUrl()`, then `Xrm.Utility.getGlobalContext().getClientUrl()`, then the page origin. From that host it builds the three routing fields the Azure Function expects:

| Field | Value | Example |
| --- | --- | --- |
| `environmentUrl` | The environment address | `https://contoso.crm.dynamics.com` |
| `environmentApiUrl` | The same host with `api` after the organization name | `https://contoso.api.crm.dynamics.com` |
| `cloud` | The cloud that the host suffix belongs to | `Commercial` |

| Host suffix | `cloud` |
| --- | --- |
| `.crm.microsoftdynamics.us` | `GCCHigh` |
| `.crm.appsplatform.us` | `DoD` |
| `.dynamics.cn` | `China` |
| `.crm9.dynamics.com` | `GCC` |
| `.dynamics.com` | `Commercial` |

The suffixes are tested in this order, the same one the Function uses. The MPP and Excel imports also send a `correlationId` generated by the control.

The Function accepts the request only when the three fields are consistent, and imports into that environment. Without them it would fall back to its fixed legacy environment (`DataverseUrl`), so the control never sends a request without them: on a page whose host is not a Dataverse environment, such as the local test harness, it shows an error instead.

Above the import button, the control shows the environment and cloud it will import into. Below the status, it shows the correlation id of the request, the one the Function confirms in its `202 Accepted` response. It also warns when that response does not confirm the same environment, which happens with a Function version that predates environment routing.

Each environment where the control is installed needs:

- Its origin in the Function App CORS settings, for example `https://contoso.crm.dynamics.com`. See [Azure configuration](#azure-configuration).
- An application user for the Function's identity, with a security role that can write projects.
- The PO Copy Project Configuration record with code `1000`, which the imports read.

## HTTP contract

### MPP import

```http
POST https://dc-copyproyectfromtemplate.azurewebsites.net/api/ImportMppToProject
Accept: application/json
x-functions-key: FUNCTION_KEY
Content-Type: multipart/form-data; boundary=GENERATED_BY_THE_BROWSER
```

| Field | Type | Description |
| --- | --- | --- |
| `targetProjectId` | Text | GUID of the selected `msdyn_project` record. |
| `environmentUrl` | Text | Address of the environment that hosts the control. |
| `environmentApiUrl` | Text | Web API address of that environment. |
| `cloud` | Text | `Commercial`, `GCC`, `GCCHigh`, `DoD` or `China`. |
| `correlationId` | Text | GUID generated by the control to trace the import. |
| `file` | File | Microsoft Project `.mpp` file. |

The control does not convert the file to Base64 and does not manually set the `Content-Type` header. The text fields are sent before the file.

A `202 Accepted` response contains `id`, `statusUri`, `environment`, `cloud` and `correlationId` as confirmed by the Function.

### Operation status

```http
GET https://dc-copyproyectfromtemplate.azurewebsites.net/api/ImportMppToProject/INSTANCE-ID
Accept: application/json
x-functions-key: FUNCTION_KEY
```

This is the `statusUri` of the `202 Accepted` response: the address of the starting request with the instance id appended (`ImportMppToProject`, `ImportExcelToProject` or `CopyProyectFromTemplate`). The same function answers the `GET`, so the Function Key of that endpoint works for both. The control sends the key the way the starting request did: the `x-functions-key` header, or the `code` parameter of the configured URL, which it appends to `statusUri`.

The endpoint answers `202` while the operation runs and `200` once it finished, with `runtimeStatus`, `createdTime`, `lastUpdatedTime`, `output` (the result, such as `message` and `skippedResources`) and `error` (the reason when `runtimeStatus` is `Failed`). An unknown id, or one started by another endpoint, answers `404`.

It replaces the Durable Functions `statusQueryGetUri` of earlier Function versions, which carried the Durable system key: that key can also terminate and purge orchestrations.

### Excel import

```http
POST https://dc-copyproyectfromtemplate.azurewebsites.net/api/ImportExcelToProject
Accept: application/json
x-functions-key: FUNCTION_KEY
Content-Type: multipart/form-data; boundary=GENERATED_BY_THE_BROWSER
```

| Field | Type | Description |
| --- | --- | --- |
| `targetProjectId` | Text | GUID of the selected `msdyn_project` record. |
| `environmentUrl` | Text | Address of the environment that hosts the control. |
| `environmentApiUrl` | Text | Web API address of that environment. |
| `cloud` | Text | `Commercial`, `GCC`, `GCCHigh`, `DoD` or `China`. |
| `correlationId` | Text | GUID generated by the control to trace the import. |
| `file` | File | Excel `.xlsx` project file. |

The request is sent to the URL configured in `excelFunctionUrl`.

### Project import

```http
POST https://dc-copyproyectfromtemplate.azurewebsites.net/api/copyproyectfromtemplate?code=FUNCTION_KEY
Accept: application/json
Content-Type: application/json
```

```json
{
  "sourceProjectId": "SOURCE-PROJECT-GUID",
  "targetProjectId": "DESTINATION-PROJECT-GUID",
  "environmentUrl": "https://contoso.crm.dynamics.com",
  "environmentApiUrl": "https://contoso.api.crm.dynamics.com",
  "cloud": "Commercial"
}
```

The source GUID comes from the Source project search box and the destination GUID comes from the Destination project search box. The request is sent to the URL configured in `copyProjectFunctionUrl`. This endpoint does not read a correlation id: the Function generates one and returns it in the `202 Accepted` response, and the control displays that one.

### Connection test

```http
GET https://dc-copyproyectfromtemplate.azurewebsites.net/api/testconnection?code=FUNCTION_KEY&environmentUrl=https%3A%2F%2Fcontoso.crm.dynamics.com&environmentApiUrl=https%3A%2F%2Fcontoso.api.crm.dynamics.com&cloud=Commercial
Accept: application/json, text/plain
```

The control appends the three routing fields to the configured URL, so the test checks the Function's access to the environment that hosts the control. The response body is rendered using `textContent`; JSON responses are formatted with indentation and text responses are displayed unchanged. The request uses `testConnectionFunctionUrl`, has a 30-second timeout, and does not require any project or file selection. The final result is hidden automatically after 15 seconds.

### Project Online project list

When `pwaProjectsFunctionUrl` is configured, the control posts the configured PWA URL to it:

```json
{
  "pwaSiteUrl": "https://contoso.sharepoint.com/sites/pwa",
  "configurationId": "PO-COPY-PROJECT-CONFIGURATION-GUID"
}
```

The response can be an array or an object containing `projects`, `Projects`, `value`, `Payload`, or an OData verbose `d.results` array. Project fields follow the ProjectData names `ProjectId`, `ProjectName`, `ProjectStartDate`, `ProjectFinishDate`, and `ProjectOwnerName`.

### Project Online task list

When a project is expanded and `pwaProjectTasksFunctionUrl` is configured, the control posts:

```json
{
  "pwaSiteUrl": "https://contoso.sharepoint.com/sites/pwa",
  "projectId": "PROJECT-ONLINE-GUID",
  "configurationId": "PO-COPY-PROJECT-CONFIGURATION-GUID"
}
```

The task response supports the same array wrappers and the fields `TaskId`, `TaskName`, `TaskStartDate`, `TaskFinishDate`, and `TaskDuration`. Tasks can also be supplied inline through a `Tasks` or `tasks` array in the project-list response.

## Control properties

| Property | Required | Default | Description |
| --- | --- | --- | --- |
| `functionUrl` | Yes | — | HTTPS URL of `ImportMppToProject`. |
| `functionKey` | No | — | Key sent through `x-functions-key`. It can be omitted when the URL already contains `?code=`. |
| `copyProjectFunctionUrl` | For project import | — | Full HTTPS URL of `CopyProyectFromTemplate`; it may include its own `?code=` Function Key. |
| `excelFunctionUrl` | For Excel import | — | Full HTTPS URL of `ImportExcelToProject`; it may include its own `?code=` Function Key. |
| `testConnectionFunctionUrl` | For connection test | — | Full HTTPS URL of `TestConnection`; it may include its own `?code=` Function Key. |
| `pwaProjectsFunctionUrl` | For Project Online browsing | — | Full HTTPS URL used to list projects from the configured PWA site. |
| `pwaProjectTasksFunctionUrl` | For Project Online task expansion | — | Full HTTPS URL used to list tasks for one PWA project. |
| `pwaConnectionPageName` | For self-service Project Online authentication | — | Logical name of the Custom Page opened by **Connect to Project Online**. |
| `maxFileSizeMb` | No | 210 | Local maximum file size validated before upload. |
| `requestTimeoutSeconds` | No | 600 | Maximum time allowed to upload the file and receive the initial `202` response. |

Demo URL:

```text
https://dc-copyproyectfromtemplate.azurewebsites.net/api/ImportMppToProject
```

Configure the Function Key in `functionKey` without the `code=` prefix. If the copied key contains URL-encoded characters such as `%3D`, the control decodes them before sending the request.

Configure the project-copy endpoint separately in `copyProjectFunctionUrl`, for example:

```text
https://dc-copyproyectfromtemplate.azurewebsites.net/api/copyproyectfromtemplate?code=COPY_FUNCTION_KEY
```

Configure the Excel endpoint separately in `excelFunctionUrl`, for example:

```text
https://dc-copyproyectfromtemplate.azurewebsites.net/api/ImportExcelToProject?code=EXCEL_FUNCTION_KEY
```

Configure the diagnostic endpoint separately in `testConnectionFunctionUrl`, for example:

```text
https://dc-copyproyectfromtemplate.azurewebsites.net/api/testconnection?code=TEST_CONNECTION_FUNCTION_KEY
```

## Azure configuration

Add the origin of every environment where the control is installed to the Function App CORS settings, for example:

```text
https://dctraining.crm.dynamics.com
https://contoso.crm.dynamics.com
```

The browser sends the upload, the copy request, the connection test and the status polling from that origin, so a missing origin fails with "Azure could not be reached". Allowing `*` also works: CORS does not replace the Function Key, which every request still needs.

Review these Function App settings as well:

```text
FUNCTIONS_REQUEST_BODY_SIZE_LIMIT=220200960
MppMaxUploadBytes=220000000
MppImportContainer=mpp-imports
MppSourceTimeZone=America/Argentina/Buenos_Aires
```

## Build and deploy

```powershell
npm install
npm run build -- --buildMode production
dotnet restore .\MppUploaderPcf.pcfproj
pac pcf push --solution-unique-name "DC_ImportFromMPP"
```

The `.pcfproj` references `Microsoft.PowerApps.MSBuild.Pcf` through `PackageReference`, allowing the temporary wrapper generated by `pac pcf push` to restore the package before building the control.

## Security

A Function Key configured in a PCF can be inspected from the browser. This also applies when the key is included in `copyProjectFunctionUrl`. For production, rotate exposed keys and protect the endpoint with Microsoft Entra ID or Azure API Management.
